# Исправления по исследованию: v1.2.0

Дата: 24 ноября 2026 года. Исходный объект исследования — `v1.1.0`, commit
`45ccee95610328be1bdb23e5ae81325b6540f4d6`. [Исходный отчёт](report.md) и его
протоколы сохранены как исторический снимок. Этот документ описывает последующие
изменения приложения; результаты исходного аудита не переписаны задним числом.

## Исправление рекомендации о Gunicorn

В исходном отчёте предлагался patch-релиз 26.2.2 на основании GitHub release notes.
При подготовке установки выяснилось, что пакет этой версии в PyPI отсутствует:
наличие страницы релиза не доказывает доступность устанавливаемого артефакта.
Выбрана реально опубликованная **27.0.1**, проверены установка, зависимости,
ограничение chunk parser и настоящий изолированный WSGI-запуск.
[PyPI Gunicorn 27.0.1](https://pypi.org/project/gunicorn/27.0.1/).

## Локальные проверки

- **92 pytest tests passed**; в исходном снимке было 54.
- Ruff lint/format, строгий mypy для 24 Python-файлов, TypeScript checkJs,
  Prettier и `pip check` прошли.
- `pip-audit` нового полного runtime-набора: десять пакетов, известных записей
  уязвимостей в использованном сервисе на момент проверки нет.
- Wheels разрешены/скачаны для macOS arm64 и Linux x64, CPython 3.11/3.12.
  Эти проверки доступности не являются исполнением чужой ОС/Python.
- Изолированный настоящий Gunicorn завершил in-flight запрос с HTTP 200 после
  SIGTERM, затем вышел с кодом 0. Снимок версии в этом smoke ещё показывает
  `1.1.0`: тест проведён до изменения номера релиза, но после обновления Gunicorn.
- Headless Chrome, viewport 390: Enter и 0 ₽, revision conflict, draft/focus/photo,
  история архива, потерянный ответ создания и оба исхода уведомления проверены;
  JavaScript page errors — 0. Тестовый сервер и Chrome остановлены.

Сохранённые протоколы исправлений: [fix-evidence](fix-evidence/).
CI для конкретного исходного commit является отдельной проверкой:
[GitHub Actions](https://github.com/PaVeLlLlLX/friends-auction/actions/workflows/checks.yml).
Контейнерные изменения требуют успешного CI container smoke до переключения

## Границы результата

Публичные лимиты действуют внутри одного WSGI-процесса. Они закрывают найденное
отсутствие прикладного ограничения, но не устанавливают устойчивость домашнего
канала/Cloudflare к распределённой атаке. Внешние лимиты и доступность Quick Tunnel
остаются отдельной эксплуатационной границей.

Runtime версии закреплены, но hash-enforced installation не внедрён. Сохранены
wheel hashes проверенных артефактов; это не битовая воспроизводимость всей ОС и
не независимая аттестация процесса. Лицензия не выбрана автоматически за владельца:
README продолжает явно сообщать, что репозиторий публичный, а LICENSE отсутствует.

Неопределённая попытка создания и её замороженный payload сохраняются в памяти
текущего WebView, включая переходы между вкладками приложения. Полный перезапуск
WebView не восстанавливает черновик с файлами; перед новой публикацией после такого
перезапуска следует проверить каталог. Серверная дедупликация гарантирует один
результат для повторов с тем же UUID, а не угадывает одинаковые вещи по названию.

Автоматическая очистка охватывает настроенное хранилище и отмеченные копии.
Исходные импорты, другие окружения, внешние backups, системные snapshots и
доставленные сообщения имеют отдельные границы контроля:
[политика хранения](../../data-retention.md). Не заявляются физическое стирание
всех блоков, удаление всех копий Telegram или прохождение реальных iOS/Android
устройств. Нормативные вопросы исходного скрининга не объявлены юридически
разрешёнными изменением кода.

## Выпуск

В релиз не должны попадать credentials, рабочая БД, фотографии, private logs и
резервная копия. Переключение выполняется на отдельный каталог `v1.2.0` с новой
виртуальной средой, после согласованного приватного snapshot. Существующая БД
мигрирует аддитивно: лоты, одобрения и история ставок сохраняются. Пакетное
происхождение, доступность HTTP/HTTPS и свежесть worker проверяются после запуска;
настоящие ставки и заявки для проверки не создаются.
