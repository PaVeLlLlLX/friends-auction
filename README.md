# Friends Auction

Telegram Mini App для аукционов с ручным допуском участников. Приложение объединяет публичный каталог лотов, приём ставок и инструменты организатора. Telegram используется для идентификации пользователей и доставки уведомлений; оплата и передача вещей согласуются вне приложения.

## Возможности

- Публичный просмотр лотов без авторизации.
- Заявки на участие с именем и фамилией; одобрение действует на все лоты.
- Начальная цена от 0 ₽, индивидуальный шаг и повышение на несколько шагов.
- Проверка актуальной цены и последовательная обработка конкурирующих ставок в транзакции SQLite.
- До шести фотографий на лот: JPEG, PNG, WebP и HEIC/HEIF, до 36 МБ на запрос. Изображения перекодируются в JPEG с удалением исходных метаданных.
- Личная история ставок, подписки на лоты и уведомления через бота.
- Управление заявками, просмотр истории ставок, снятие лотов и учёт передачи вещей.
- Выбор следующего участника после отказа победителя с уведомлением по решению организатора.

Название, описание, состояние, начальную цену и шаг можно изменять до первой ставки. Замена фотографий в редакторе лота не поддерживается.

## Архитектура

| Компонент | Назначение |
|---|---|
| Веб-приложение | Flask API, проверка Telegram `initData`, авторизация, ставки и управление лотами. |
| Интерфейс | HTML, CSS и JavaScript без этапа сборки. Открытые страницы запрашивают обновления примерно раз в три секунды. |
| Фоновый процесс | Отправка уведомлений, обработка `/start` при включённом polling и очистка данных по сроку хранения. |
| Хранилище | База SQLite и каталог фотографий на локальном диске сервера. |
| Локализация | Общий словарь сообщений для интерфейса, сервера и бота в `static/ru.json`. |

Приложение рассчитано на один сервер с постоянным диском. Веб-приложение и фоновый процесс используют одну базу и один каталог фотографий. Горизонтальное масштабирование на несколько независимых узлов не предусмотрено.

## Требования

- Для запуска без контейнеров — Python 3.11 или новее, macOS или Linux и зависимости из [`requirements.txt`](requirements.txt). Gunicorn и файловая блокировка фонового процесса требуют Unix-подобной среды.
- Для запуска в контейнерах — Docker Engine с плагином Compose либо Docker Desktop. Установка Python на хосте не требуется. Инструкции: [Docker Compose](https://docs.docker.com/compose/install/).
- Для интеграции с Telegram — бот, созданный через [@BotFather](https://t.me/BotFather), и публичный HTTPS-адрес приложения.
- Для временного HTTPS-адреса в интеграционном окружении — [`cloudflared`](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/).

## Установка

Используйте установленный Python версии 3.11 или новее. В примере указан Python 3.12; при другой версии замените имя исполняемого файла. Системный `python3` в macOS может быть старше необходимой версии.

```sh
git clone https://github.com/PaVeLlLlLX/friends-auction.git
cd friends-auction
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Все последующие команды выполняются из корня репозитория.

В macOS также доступны исполняемые файлы `demo.command`, `configure-telegram.command` и `integration.command`. Каждый создаёт `.venv` при необходимости и устанавливает зависимости; после сбоя установки повторный запуск повторяет попытку. Для Linux используйте команды Python ниже.

## Демонстрационный режим

```sh
.venv/bin/python demo.py
```

Сервер запускается на `127.0.0.1:8080`. Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080) в браузере на узле, где запущен процесс. Для остановки используйте `Ctrl+C`.

Демонстрационный режим создаёт примеры лотов и позволяет переключать роли гостя, участников и организатора. Бот и сетевое подключение к Telegram для проверки сценариев не требуются. Данные сохраняются отдельно в `data/demo.sqlite3` и `data/demo-photos/`.

Демонстрация использует общие даты окончания торгов и хранения из раздела «Параметры аукциона». После этих дат соответствующие действия и доступ к данным ограничиваются так же, как в рабочем режиме.

Демонстрационный сервер должен оставаться доступным только через loopback-интерфейс: переключение ролей в этом режиме заменяет авторизацию.

## Интеграционное тестирование в Telegram

Интеграционный режим использует настоящую авторизацию Telegram, отдельное хранилище и явную маркировку тестовых ставок. Он предназначен для проверки взаимодействия Mini App, бота и сервера.

### Подготовка

Создайте отдельного бота для тестового окружения. Скрипт настройки получает обновления через `getUpdates`; бот не должен использоваться другим polling-процессом или иметь активный webhook.

Установите `cloudflared` и обеспечьте наличие исполняемого файла по пути `.tools/cloudflared`. Например, для macOS с Homebrew:

```sh
brew install cloudflared
mkdir -p .tools
ln -s "$(command -v cloudflared)" .tools/cloudflared
```

Если файл или ссылка `.tools/cloudflared` уже существует, повторное создание не требуется.

### Настройка и запуск

```sh
.venv/bin/python scripts/setup_testing.py
.venv/bin/python scripts/start_testing.py
```

Скрипт настройки запрашивает токен со скрытым вводом, предлагает отправить `/start` боту и подтвердить Telegram-аккаунт организатора. Конфигурация сохраняется в `data/testing-config.json` с правами доступа `0600`.

Скрипт запуска поднимает веб-приложение на `127.0.0.1:8090`, создаёт Cloudflare Quick Tunnel, обновляет кнопку меню бота и запускает фоновый процесс. Для проверки разграничения прав используются аккаунты организатора и участника. Приложение открывается через кнопку бота в Telegram.

Тестовое окружение работает, пока активны процессы запуска и сетевое соединение. `Ctrl+C` останавливает его компоненты. Адрес туннеля меняется при перезапуске; актуальная кнопка доступна в меню бота или в новом ответе на `/start`.

Если компонент не запускается, скрипт сообщает о причине и сохраняет последние строки диагностики в `data/testing-launch-*.log` с правами `0600`. Токен бота и URL удаляются из этой диагностики; перед передачей файла другим людям проверьте его содержимое. Если отсутствует исполняемый файл, сообщение указывает его путь. Для замены конфигурации сохраните резервную копию `data/testing-config.json` вне репозитория, удалите исходный файл и повторите настройку.

База и фотографии тестового окружения находятся в `data/testing.sqlite3` и `data/testing-photos/`. Они не переносятся в рабочее окружение автоматически.

## Конфигурация

Веб-приложение и фоновый процесс получают настройки из переменных окружения. Файлы `.env` автоматически не загружаются. Для рабочего окружения задавайте одинаковые параметры хранилища и бота в обоих процессах.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота. Обязателен вне демонстрационного режима. | Не задан |
| `TELEGRAM_ADMIN_ID` | Числовой Telegram ID организатора. Обязателен вне демонстрационного режима. | Не задан |
| `AUCTION_DB` | Путь к базе SQLite. | `data/auction.sqlite3` |
| `AUCTION_UPLOADS` | Каталог загруженных фотографий. | `data/photos/` |
| `AUCTION_DEMO` | `1` включает демонстрационный режим с переключением ролей. | Выключено |
| `AUCTION_TRIAL` | `1` включает интеграционный режим: маркировку тестовых ставок и обработку IP-заголовка от локального Cloudflare Tunnel. | Выключено |
| `AUCTION_BOT_POLL` | `1` включает обработку личных команд `/start` фоновым процессом через `getUpdates`. | Выключено |
| `AUCTION_APP_URL` | HTTPS-адрес для кнопки в ответе на `/start`. Требуется при `AUCTION_BOT_POLL=1`. | Не задан |
| `PORT` | Порт встроенного сервера при запуске `python run.py`; не используется Gunicorn. | `8080` |

Скрипты `demo.py` и `scripts/start_testing.py` самостоятельно задают параметры соответствующих окружений. `AUCTION_TRIAL=1` предполагает доступ через доверенный локальный Cloudflare Tunnel; этот режим не предназначен для произвольной схемы проксирования.

### Параметры аукциона

Дата завершения и срок хранения определены константами `END` и `DELETE_AFTER` в [`auction/app.py`](auction/app.py). Редактирование этих параметров через интерфейс или переменные окружения не реализовано.

| Параметр | Значение в исходном коде |
|---|---|
| Завершение приёма ставок | 12 декабря 2026 года, 23:59:00, UTC+7 |
| Окончание срока хранения | 1 февраля 2027 года, 00:00:00, UTC+7 |
| Ежедневная сводка | Начиная с 18:00, UTC+7, при наличии изменений |

Ставки принимаются строго до времени завершения; продление не предусмотрено. Для другого аукциона необходимо изменить константы, согласовать отображаемые даты в [`static/ru.json`](static/ru.json) и проверить соответствующие сценарии.

## Развёртывание

Для постоянного размещения требуются HTTPS reverse proxy, постоянный диск и управление жизненным циклом процессов. Параметры `AUCTION_DEMO` и `AUCTION_TRIAL` должны быть выключены.

### Без контейнеров

После установки зависимостей и настройки обязательных переменных окружения запустите веб-приложение:

```sh
.venv/bin/gunicorn --bind 127.0.0.1:8080 --workers 1 --threads 4 run:app
```

В отдельном процессе с теми же настройками запустите обработчик уведомлений:

```sh
.venv/bin/python -m auction.worker
```

На одном узле допускается один экземпляр обработчика для каталога данных; повторный запуск блокируется файловой блокировкой. Для ответов на `/start` дополнительно задайте `AUCTION_BOT_POLL=1` и `AUCTION_APP_URL`. Настройте кнопку Mini App у бота на публичный HTTPS-адрес.

Reverse proxy должен ограничивать размер запроса в соответствии с лимитом приложения — 36 МБ — и обеспечивать контроль частоты запросов. Встроенные ограничения приложения действуют в пределах одного процесса. Для эксплуатации также требуются синхронизация времени, мониторинг, восстановление процессов после сбоя и проверенное резервное копирование хранилища.

Описание интеграций: [Telegram Mini Apps](https://core.telegram.org/bots/webapps) и [Gunicorn в документации Flask](https://flask.palletsprojects.com/en/stable/deploying/gunicorn/).

### Docker Compose

Создайте локальную конфигурацию из шаблона:

```sh
cp .env.example .env
chmod 600 .env
```

В `.env` укажите `TELEGRAM_BOT_TOKEN` и числовой `TELEGRAM_ADMIN_ID`. Для ответов на `/start` задайте `AUCTION_BOT_POLL=1` и `AUCTION_APP_URL=https://your-domain.example`. Polling одного бота должен выполнять только один процесс; активного webhook быть не должно. При выключенном polling кнопку Mini App настраивают отдельно в BotFather.

Запустите сервисы из корня репозитория:

```sh
docker compose config --quiet
docker compose up --build --detach
docker compose ps
```

Compose читает `.env` и запускает два сервиса из одного образа:

| Сервис | Назначение |
|---|---|
| `web` | Gunicorn с одним процессом и четырьмя потоками, порт 8080 внутри контейнера. |
| `worker` | Уведомления, необязательный polling Telegram и очистка данных; запускается после успешной проверки доступности `web`. |

По умолчанию веб-приложение доступно на [http://127.0.0.1:8080](http://127.0.0.1:8080) на Docker-хосте. Переменная `AUCTION_HTTP_PORT` в `.env` меняет опубликованный порт. Порт привязан к loopback-интерфейсу; HTTPS reverse proxy на том же хосте должен направлять запросы на этот адрес. Для открытия Mini App в Telegram нужен публичный HTTPS-домен.

Сервисы работают от UID/GID `10001:10001`, с файловой системой образа только для чтения. База `/app/data/auction.sqlite3` и фотографии `/app/data/photos/` сохраняются в общем именованном томе `friends-auction_auction-data`. `.env`, каталог `data/`, Git и инструменты разработки исключены из контекста сборки через [`.dockerignore`](.dockerignore).

При первом запуске создаётся пустое хранилище. Существующие базы и фотографии из локальных окружений не импортируются автоматически. Для переноса аукциона остановите процессы, которые изменяют исходное хранилище, сохраните резервную копию и перенесите базу вместе с её каталогом фотографий в том. Владелец перенесённых файлов должен иметь UID/GID `10001:10001`; имена фотографий и их соответствие записям базы должны сохраниться.

Управление сервисами:

```sh
docker compose logs --tail 100 --follow
docker compose down
docker compose up --build --detach
```

`down` останавливает сервисы и сохраняет том; `down --volumes` удаляет его вместе с данными. Для обновления исходников повторите `up --build --detach`. Фоновый процесс перезапускается при аварийном завершении, максимум пять раз; после успешной очистки по сроку хранения он остаётся остановленным. После перезапуска Docker Engine запустите стек командой `docker compose up --detach`, чтобы восстановить и фоновый процесс.

## Доступ и жизненный цикл данных

Гости видят каталог, фотографии, текущие цены и количество ставок. Для подачи заявки, ставок и подписок сервер проверяет подпись и срок действия Telegram `initData`. Полномочия организатора определяются Telegram ID; username используется только как справочная информация.

Имена из заявок и история ставок всех участников доступны организатору. Участник видит собственную историю. Отзыв допуска блокирует новые ставки, но не отменяет уже сделанные.

После ставки включаются уведомления об участии. Отдельная подписка позволяет следить за лотом без ставки. Участник может отключить уведомления; для их доставки необходимо начать диалог с ботом и не блокировать его. В последний час торгов обработчик отправляет напоминание и сообщения о перебитых ставках.

При сбое между принятием сообщения Telegram и сохранением результата в базе возможна повторная отправка. Доставка уведомления не гарантирует его прочтение до окончания торгов.

По истечении срока хранения API и фотографии становятся недоступны. Работающий обработчик удаляет записи из настроенной базы и JPEG-файлы из настроенного каталога фотографий, затем завершается. Если обработчик остановлен, очистка выполняется после его следующего запуска. Запуск интеграционного окружения после этого срока выполняет очистку без создания туннеля и веб-сервера. Исходные материалы, другие базы и резервные копии удаляются отдельно согласно политике хранения оператора.

Токены и рабочие данные не должны попадать в Git или публичные отчёты об ошибках. Стандартные пути в `data/` исключены из репозитория через `.gitignore`; использование других путей требует отдельной проверки. Независимый аудит безопасности не проводился.

## Разработка

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/python -m mypy
.venv/bin/python -m pytest -q
```

Функции Python имеют аннотации параметров и результата, а docstring описывают назначение и существенные условия вызова: владение соединениями, транзакции, побочные действия и обработку ошибок. Общие JSON-типы определены в [`auction/contracts.py`](auction/contracts.py), структуры учётных записей, лотов и ставок — в [`auction/models.py`](auction/models.py). Mypy проверяет приложение, служебные скрипты и тесты в строгом режиме. Ruff проверяет наличие аннотаций и документации публичных функций и модулей.

Тесты используют временные базы, вымышленные профили и поддельный токен. Внешние сообщения в Telegram не отправляются. Проверяются авторизация, разграничение доступа, конкурирующие ставки, ограничения загрузки, уведомления, очистка и локализация.

Для проверки форматирования интерфейса нужен Node.js 24 или новее. Он используется только инструментами разработки; для запуска приложения Node.js не требуется.

```sh
npm ci
npm run format:check
npm run typecheck
```

JavaScript сохраняет запуск без сборки; функции и контракты данных описаны через JSDoc. TypeScript проверяет их в режиме `checkJs` со строгими настройками из [`jsconfig.json`](jsconfig.json). Эти проверки выявляют несовместимые типы при разработке; данные HTTP и Telegram требуют отдельной проверки во время выполнения.

Исправления форматирования выполняются командами `.venv/bin/ruff format .` и `npm run format`. GitHub Actions запускает Python-проверки на версиях 3.11 и 3.12, проверку типов JavaScript и форматирование интерфейса при push и pull request. Отдельная задача собирает Docker-образ, проверяет запуск, сохранение данных после пересоздания контейнера и доступ обработчика к общему тому. Правила работы с репозиторием описаны в [AGENTS.md](AGENTS.md).

```text
auction/       API, авторизация, локализация и фоновый обработчик
scripts/       Настройка и запуск интеграционного окружения
static/        Интерфейс и словарь сообщений
tests/         Автоматические тесты
docs/          Спецификация и решения об интерфейсе
demo.py        Демонстрационное окружение
run.py         Точка входа веб-приложения
```

Проектные материалы: [спецификация](docs/specification.md) и [решения об интерфейсе](docs/design.md).
