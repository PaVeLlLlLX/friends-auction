# Спецификация аукциона

Friends Auction — один аукцион личных вещей с одним организатором. Каталог доступен публично; делать ставки могут только участники, которых одобрил организатор. Интерфейс работает в Telegram Mini App. Оплата и передача вещей происходят вне приложения.

Этот документ описывает правила текущей реализации. Установка и эксплуатация описаны в [README](../README.md), решения об интерфейсе — в [design.md](design.md).

## Роли и доступ

| Роль | Доступ |
|---|---|
| Гость | Каталог, фотографии, описание, текущая цена, количество ставок и срок окончания. |
| Пользователь Telegram | Подача заявки с именем и фамилией, подписка на лоты, собственная история ставок. |
| Одобренный участник | Ставки на все активные лоты до общего срока окончания. |
| Организатор | Создание и управление лотами, решения по заявкам, история всех ставок, выбор следующего кандидата и учёт передачи вещи. |

Сервер проверяет подпись и срок действия Telegram `initData`. Организатор определяется по постоянному Telegram ID, а не по username. Имена из заявок и сведения о других участниках доступны организатору; публичный каталог их не раскрывает.

Заявка не является ставкой и ничего не резервирует. После одобрения участник подтверждает ставку самостоятельно по актуальной цене. Отказ или отзыв допуска запрещает новые ставки, но сохраняет историю уже принятых.

## Лоты и ставки

- Лот содержит название, описание, состояние, начальную цену, шаг и до шести фотографий. JPEG, PNG, WebP и HEIC/HEIF перекодируются в JPEG; метаданные исходного изображения не сохраняются. Максимальный размер запроса — 36 МБ.
- Начальная цена может быть 0 ₽. Первая ставка равна начальной цене либо превышает её на целое число шагов. Следующая ставка превышает текущую минимум на один шаг; можно повысить цену сразу на несколько шагов.
- Участник не может повышать собственную лидирующую ставку. Для принятия ставки обязательны действующий допуск и совпадение переданной ожидаемой цены с текущей ценой сервера.
- Конкурирующие ставки обрабатываются последовательно в транзакции SQLite. Если цена изменилась, сервер отклоняет устаревшее подтверждение, а интерфейс предлагает проверить новые условия.
- Название, описание, состояние, начальную цену и шаг можно редактировать только до первой ставки. Замена фотографий в редакторе не реализована. Организатор может снять лот; история сохраняется.
- Организатор может удалить лот из каталога. Лот и его фотографии становятся недоступны публично; ставки сохраняются в личной истории участников и в архиве организатора. Подписки на удалённый лот отключаются. Если перед подтверждением появилась новая ставка, удаление требует повторного подтверждения по обновлённым данным.
- Все лоты имеют общий срок окончания. Продления и планового раннего завершения отдельных лотов нет. Сервер принимает ставки строго до установленного момента.

Параметры текущего аукциона заданы в `auction/app.py`:

| Параметр | Значение |
|---|---|
| Завершение ставок | 12 декабря 2026 года, 23:59:00, UTC+7 |
| Окончание хранения | 1 февраля 2027 года, 00:00:00, UTC+7 |
| Начало отправки ежедневной сводки | 18:00, UTC+7 |

Для другого аукциона необходимо изменить серверные константы и отображаемые даты в `static/ru.json`, затем проверить границы времени. Демонстрационный и интеграционный режимы используют те же сроки.

## Результаты и передача

Победитель — автор наибольшей действительной ставки, принятой до окончания торгов. Организатор видит результаты, историю и данные для связи; участник видит собственные ставки и свой статус. Вещи передаются самовывозом. Точный адрес, время встречи и оплату участники согласуют лично.

После отказа победителя организатор отмечает отказ и рассматривает следующего участника по его лучшей ставке. Приложение не отправляет ему сообщение без отдельного подтверждения организатора. Для лотов без ставок решение остаётся за организатором; переоткрытие торгов и отмена отдельных принятых ставок через интерфейс не реализованы.

## Уведомления

Ставка включает подписку на сообщения о перебитой ставке и близком окончании торгов. Отдельная подписка позволяет следить за изменением ставок без участия. Обе подписки можно отключить в карточке; это не отменяет ставку.

Ежедневная сводка отправляется начиная с 18:00 по UTC+7, только при наличии новых событий, одним сообщением по интересующим участника лотам. Общей рассылки о новых лотах нет. В последний час торгов обработчик отправляет одно напоминание участнику и оперативно сообщает о перебитых ставках, объединяя события, накопившиеся к очередной обработке. В сообщениях не раскрываются личности других участников.

Для доставки пользователь должен начать диалог с ботом и не блокировать его. Статусы доступны в приложении независимо от доставки. После сбоя возможна повторная отправка сообщения, если Telegram уже принял его, а обработчик ещё не сохранил результат в базе. Уведомления не гарантируют, что участник успеет увидеть сообщение и сделать ставку до окончания.

## Хранение и эксплуатационные границы

Приложение использует один сервер с постоянным диском, SQLite, каталог фотографий и отдельный фоновый процесс. Горизонтальное масштабирование не предусмотрено. Веб-приложение и обработчик должны получать одинаковую конфигурацию хранилища и бота.

По истечении срока хранения API и фотографии недоступны. Работающий обработчик удаляет записи настроенной базы и JPEG-файлы из настроенного каталога; после остановки очистка выполняется при следующем запуске обработчика. Удаление резервных копий и исходных материалов — обязанность оператора.

Токены, Telegram ID реальных участников, пользовательские данные и резервные копии должны храниться вне Git с ограничением доступа. Для постоянной эксплуатации нужны HTTPS, ограничение частоты запросов на reverse proxy, синхронизация времени, восстановление процессов и проверенное резервное копирование. Открытый исходный код не подтверждает идентичность запущенной версии и не заменяет аудит безопасности.

Онлайн-платежи, доставка, рейтинги, несколько организаторов и торговля вещами между участниками в текущую реализацию не входят.

## Проверка перед запуском

Автоматические проверки запускаются по инструкции [README](../README.md#разработка). Дополнительно на целевых устройствах проверяются:

1. Сквозной сценарий: создание лота с фотографиями с телефона, заявка, одобрение, ставка, изменение цены другим участником и собственная история.
2. Разграничение ролей: публичный просмотр без допуска, отказ по заявке, прямые запросы к закрытым API и отсутствие чужих данных в публичных ответах.
3. Правила ставок: нулевая первая ставка, несколько шагов, одновременные подтверждения и точная граница завершения без продления.
4. Работа уведомлений, отключение подписок, отказ победителя и отдельное подтверждение следующего кандидата.
5. Перезапуск веб-приложения и обработчика, восстановление резервной копии, доступность фотографий и удаление по сроку хранения.
6. Telegram на iOS и Android, мобильные экраны, клавиатура и доступность форм. Работающие серверные тесты не подтверждают прохождение этих проверок.
